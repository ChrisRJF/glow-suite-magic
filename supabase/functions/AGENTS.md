# AGENTS (edge functions)

- Viva ISV uses _shared/vivaIsvPrepared.ts, owner+aal2 route viva-isv-demo-order and VIVA_ISV_DEMO_ENABLED (ISV credentials only); expected service-role commission identifies ISV; the temporary preview button was removed, the route stays switch-gated; why: live routes stay unchanged and salon metadata is untrusted.
- ISV finance rules (payment row before order, webhook decisions, salon view without platform fields, MFA platform-owner check, ledger-based reports) are prepared in _shared/inactive/isvFinance.ts; why: commission is platform data and must never reach salons or be counted before Viva confirms it.
- Platform commission is designed to live only in service-role tables (platform_commission_entries, platform_owners) read via an MFA-gated audited RPC, never in salon-readable payments.metadata; applied (migration 0019); viva-webhook records the margin only via record_platform_commission (_shared/platformMargin.ts) after provider verification and keeps unfinished events retryable; why: RLS cannot hide jsonb keys and a view over a readable base table is false security.
- ISV demo payments (payment_type isv_demo + isv_demo_key) are confirmed in viva-webhook only via _shared/isvDemoConfirm.ts: Viva ISV API lookup must match status F, amount, currency, order and merchant before a conditional pending->paid, with no ledger, margin or confirmed commission; why: demo confirmations must never count as revenue or rely on webhook data alone.
- Viva ISV webhooks use the separate viva-isv-webhook (core in _shared/isvWebhookCore.ts): GET returns {"key"} via ISV credentials only, POST stores 1799 only as an unverified viva_webhook_events row (source isv_webhook, key isv1799:<env>:<tx>), 503 on storage error; why: ISV POSTs are unsigned and must never change payments or commissions.
- Reminder tenant scoping and salon-local reminder windows are prepared in _shared/inactive/reminderSafety.ts (wiring in docs/prepared-patches/reminder-safety); why: editing live reminder functions auto-deploys and needs separate GO.
- ISV onboarding safety (create reuse, session-only sync, 8193/8194 as hint + ISV Retrieve, KYC-verified live gate) is prepared in _shared/inactive/isvOnboardingSafety.ts; why: ISV webhook POSTs are unsigned and activating it redeploys payment functions.
- LIVE ISV config lives in _shared/inactive/isvLiveConfig.ts (own secret names, scoped env getter, default-off VIVA_ISV_LIVE_ENABLED); sync-viva-connected-account is the only active importer (syncLiveForSession: session tenant, switch checked before any read, Retrieve decides, never source code); why: live ISV must never mix with VIVA_ENVIRONMENT, demo ISV or merchant credentials.
